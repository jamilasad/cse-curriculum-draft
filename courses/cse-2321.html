Rationale and what changed

Data structures are the working vocabulary of every later algorithms, database and systems course, and the subject of most technical interviews set by the firms our graduates work for. The course replaces Data Structures and its lab from the 2022 syllabus and absorbs Competitive Programming 1 and 2: their problem solving moves into weekly problem sets on the department's online judge, in this lab and in the Algorithms lab, and contests stay as a co-curricular activity. C++ is used as "C with the standard library": students arrive from CSE-1221 with pointers and malloc, build each structure once by hand to see how it works and what it costs, and then use the standard-library version. Because an AI assistant produces a textbook linked list or heap in seconds, sometimes with a defect, the course also trains the checking skill: students review instructor-supplied AI-generated implementations, find the defects by tracing and testing, and fix them. Left out on purpose: balanced-tree deletion and correctness proofs, red-black tree implementation, weighted shortest paths and algorithm design techniques (CSE-2421), and anything of classes beyond a struct with member functions, such as inheritance and writing templates (CSE-2325, taught in Java in the same semester).

Minimum competency

Every passing student can do the following on a lab machine with no AI tool, no internet and only the offline standard-library reference:

  • Given a sequence of 8–10 operations, draw the exact state of a stack, a queue, a hash table with chaining, a binary search tree and a binary min-heap after each one.
  • Implement a singly linked list with insert at front and back, delete by value and reverse, which passes the supplied tests and reports no leak or invalid access under AddressSanitizer.
  • Given a 30–40 line implementation of a list, stack, queue or heap operation with one defect, find the defect with a test or a trace, explain it and fix it.
  • For a short problem statement, choose among vector, list, stack, queue, unordered_map, map/set and priority_queue, state the cost of the operations used, and solve it within the judge's time limit for n up to 10^5.
  • Read an edge list into an adjacency list and use BFS to find the fewest-edge path between two vertices, or report that none exists.

Stretch goals

  • Implement an AVL tree with insertion and deletion, or a trie for prefix search, with a test file and a timing comparison against std::set.
  • Complete the challenge tier of every problem set and join the co-curricular contest training, which works from Laaksonen's handbook.
  • Replace the chained hash table with open addressing and show, with a crafted set of keys, how a poor hash function turns expected O(1) lookup into O(n).

Weekly plan — theory

Each structure is taught in the same order: draw it, trace its operations, cost them, build it by hand in the lab, then use the library version. Graph and tree terms are taken from CSE-1123. The mid-term covers weeks 1–7.

Weekly plan — lab

CSE-2322 Data Structures Lab · Lab · 1.5 credits · 3 contact hours a week

Each three-hour session has a 15-minute tracing warm-up on paper, a build-by-hand exercise with supplied tests (about 90 minutes), then the library version and the week's problem set on the department's online judge. Problem sets have three tiers: core (three problems, required for the weekly check-off), standard and challenge. Each set stays open until the next session; together they carry the work of the former Competitive Programming courses.

Assessment

Theory. The written mid-term and final (80) are made of the parts below; tracing, defect finding and structure choice together carry about 55% of the marks:

  • Tracing (about 25%): draw a structure after a given sequence of operations, such as a chained or probed hash table, a BST after inserts and a delete, a heap after inserts and two extract-min operations, an AVL tree after inserts with each rotation named, or the queue contents and visiting order of a BFS.
  • Defects (about 15%): a 20–40 line C++ function and a failing test are given, some taken from AI-generated code; locate the faulty line, explain the fault and correct it, or write an input that exposes it.
  • Choosing a structure (about 15%): a short case (a ticket queue, a dictionary lookup, a leaderboard, a road network) with its operations and sizes; choose a structure, give the cost of each operation and say why the closest alternative is worse.
  • Complexity (about 15%): big-O of given code fragments; amortised cost of a growing array; whether a stated approach meets a time limit for a given n.
  • Write (about 20%): a function of 10–25 lines, such as reversing a linked list, checking the BST property, level-order traversal or BFS on an adjacency list; small syntax slips are not penalised.
  • Recall (about 10%): definitions and properties, such as the heap property or the load factor.

Continuous assessment (20): ten-minute tracing quizzes at Level 0 in most weeks, best eight counted (10); four assignments at Level 1 (10): a complexity set; an AI-review assignment, in which two instructor-supplied AI-generated implementations are checked, their defects explained and fixed, and the exposing tests written; a one-page structure-choice case; and a graph-modelling exercise. As in CSE-1121, the mark is given only after the student explains one randomly chosen part in class.

Notes for the instructor

In the planned public view this section is shown to the committee only (specification 3.4).

  • The usual failure is pointer work: a node lost while relinking, a null pointer followed, a heap index off by one. Require the box-and-arrow or array drawing before any code is accepted at the bench, and hand back code that does not match its drawing. Students who can recite that hash lookup is O(1) but cannot say when it is not need the week 6 load-factor experiment, not a repeated lecture.
  • Support for the weaker 85%: core-tier problems are reachable by a student who finished that week's by-hand exercise, and their worked solutions are walked through at the start of the next session. A student who fails two tracing quizzes in a row, or scores under half in practical test 1, joins a weekly support hour run by the lab instructors with peer mentors from the strongest students; there they work from starter files that already contain the function skeletons and tests, so the effort goes into the pointer logic. Practice papers in the format of the Core Competency Assessment (CSE-2440) are given out in week 14. At the bench and in the viva a student may explain in Bangla; the technical terms stay in English.
  • Keep C++ to structs with member functions, constructors and destructors, references, new/delete and the standard containers; no inheritance and no template writing. Agree terms with the CSE-2325 teacher so that "class", "constructor" and "reference" are not explained in conflicting ways in the same weeks.
  • Students are at Level 1: an assistant may explain a compiler error or a concept, but may not write a structure or a judge solution. Judge solutions are easy to obtain from an assistant, so the bench explanation decides the problem-set marks. For the AI-review exercises, generate the code with an assistant before the semester, verify every defect yourself and keep the prompt and output on file; include some correct implementations, so that students argue from tests instead of assuming a defect exists. Tell students that this review is the work they will do from semester 4, when lab projects move to Level 2.

About this group of courses: Programming and Algorithms

These seven packages form the programming spine of semesters 1 to 4. Programming I (Python) builds the habits of tracing, decomposing, testing and debugging, and the Developer Tools & Technical Communication Lab supplies the shell, Git, editor and writing skills that every later lab assumes. Programming II (C) adds the memory model; Data Structures (C++) and Object-Oriented Programming & Design (Java) build on it in semester 3, and Algorithms in semester 4 turns structures into design techniques. The Core Competency Assessment then checks, unaided, the floor these courses are meant to produce, before students move on to the track courses and the capstone. while permitted AI use rises from Level 0 in semester 1 to Level 2 in later projects and stays at Level 0 in every test, viva and examination.
