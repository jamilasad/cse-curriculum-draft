Rationale and what changed

Security moves from a 3-credit course in semester 8 to a 4-credit course in semester 6, so that every student has it before track and capstone work and so that it can use the application built in semester 4. Cryptography is taught at the level of correct use: which primitive for which job, through which library, with which mistakes to avoid; number theory and proofs are left out. Exploit development is limited to one stack overflow in a sandbox, enough to show why memory safety matters. The security of AI systems is new, and students meet it from the builder's side in CSE-3660 in the same semester. The legal context is described in general terms, and students are told to check the law in force where they work. By hand first: students exploit and fix each class of flaw manually and write a threat model on paper. With tools afterwards: scanners, intercepting proxies and AI assistants, whose findings they must reproduce and explain.

Minimum competency

  • Draw a data-flow diagram with trust boundaries for a simple web application and list at least six threats, each with a mitigation.
  • Choose the right primitive for a stated need (store a password, check a file's integrity, encrypt a file for one recipient, authenticate a message) and say why a fast unsalted hash or ECB mode is wrong where it is.
  • Exploit and then fix an SQL injection and a stored cross-site scripting flaw in a training application.
  • Capture a login in Wireshark with and without TLS and say what an eavesdropper learns in each case; scan a lab host with Nmap and interpret the open ports.
  • Solve beginner-level capture-the-flag tasks in at least three categories and write a reproducible account of each.

Stretch goals

  • Write a working exploit for a stack buffer overflow, then explain or defeat each protection (stack canary, non-executable stack, address randomisation) as it is switched on.
  • Compete in a public competition such as picoCTF and publish write-ups.
  • Report a real vulnerability to an open-source project through its disclosure process, or sit ISC2 CC or CompTIA Security+.

Assessment

Theory (100). Written mid-term and final (80). At least half the marks are application and analysis: build a threat model for a described system; find the vulnerability in a printed C function, SQL-building handler or HTML template, describe an attack and write the fix; choose primitives for a scenario, or find the misuse in a given design (passwords encrypted with a hard-coded key, a message encrypted but not authenticated); say what traffic a given firewall rule set allows on a given network diagram; reconstruct what happened from a log extract; find the injection path in an AI assistant that reads customer email and can call tools, and propose controls; decide what a tester may and may not do in a described engagement, and how a discovered flaw should be disclosed. Recall is at most a fifth; lists of port numbers and acronyms are not examined. Continuous assessment (20): Level 0 quizzes (10); two assignments (10), a threat model of a service the student uses and a written analysis of a published breach report.

Lab (100). Weekly lab work and lab record 30, earned by flags captured and write-ups; two supervised practical tests at Level 0 in weeks 6 and 12, 30; lab project 25; individual viva 15. The project, done in groups of three or four, is the hardening of an application the students built earlier, normally the CSE-2434 product: threat model, ranked findings, fixes with regression tests, before-and-after evidence, and a note on the risk that remains. A student who cannot explain their own work in the viva does not pass the lab.

Resources

  • Textbooks: Stallings and Brown, Computer Security: Principles and Practice; van Oorschot, Computer Security and the Internet: Tools and Jewels; Anderson, Security Engineering; Du, Computer & Internet Security: A Hands-on Approach; Aumasson, Serious Cryptography.
  • References: the OWASP Top 10, the OWASP Cheat Sheet Series and the OWASP Top 10 for LLM Applications; MITRE ATT&CK; the SEED Labs.
  • Software, all free: VirtualBox; Kali Linux; OWASP Juice Shop and DVWA; Burp Suite Community Edition or ZAP; Wireshark; Nmap; OpenSSL; GnuPG; John the Ripper or hashcat; gdb; CTFd for scoring; picoCTF and OverTheWire for practice.
  • Hardware: lab computers with enough memory to run two virtual machines, on host-only virtual networks or a lab network separated from the campus network.

Notes for the instructor

In the planned public view this section is shown to the committee only (specification 3.4).

  • Ethics, safety and law come first. Students sign rules of engagement in week 1; every attack stays inside the isolated lab; scanning or attacking any university or outside system is a disciplinary matter. On law, give principles and not legal advice, and invite a practitioner or the university's legal officer for part of week 14.
  • Common failure: running tools without understanding. Write-ups must explain why the attack works and how the fix stops it, and both practical tests include tasks that tools alone do not solve.
  • Weaker students: the capture-the-flag format gives frequent small successes and suits mid-level students. Split every lab into floor flags that everyone must capture and bonus flags, sell hints for points instead of withholding them, and pair students in weekly labs while keeping the tests individual.
  • AI: assistants solve many beginner flags and explain exploits well, so weekly labs allow them with disclosure and the tests run offline on variants of the tasks. Teach also that pasting client code, logs or secrets into an outside assistant is itself a leak.

About this group of courses: Software, Data, AI and Security Core

These six packages run from semester 4 to semester 6 and carry the part of the core in which students build, secure, deploy and extend real software. Database Systems and the Software Engineering package share semester 4: the database course teaches SQL early enough for the studio to use it, and the web application built in the studio becomes an object that later courses return to. Artificial Intelligence & Machine Learning (semester 5) gives the foundations and the habit of honest evaluation that the AI Application & Agent Engineering Studio (semester 6) turns into a shipped product. In semester 6, Information Security attacks and hardens the semester-4 application and Distributed Systems & Cloud Computing containerises, deploys and monitors it, so each student meets the same piece of software as its builder, its attacker and its operator.
