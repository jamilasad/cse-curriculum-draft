Rationale and what changed

This course replaces Theory of Computation and the Compiler course with its lab (7 credits in the 2022 syllabus) with one 3-credit course. Few graduates will build a compiler, but all of them write regular expressions, read grammars, parse data formats, rely on type checkers and linters, and need to know that some problems cannot be solved by any program. The course runs in two halves: automata and computability (weeks 1–7), then language implementation with programming-language concepts taught alongside it (weeks 8–14). Formal proof is limited to two set pieces, the pumping lemma on standard examples and the halting problem; other results are stated and illustrated. Left out: construction of LR parsing tables by hand, normal-form conversions, register allocation, data-flow analysis, and laboratory work with scanner and parser generators. The practical side once carried by the Compiler lab is carried by a mini-project in which each student writes a small interpreter.

Minimum competency

  • Draw a deterministic finite automaton for a simple token pattern (an identifier, a decimal number, binary strings ending in 01), trace a string through it, and write the matching regular expression.
  • Given a small grammar and a string, give a leftmost derivation and the parse tree; show that a given expression grammar is ambiguous.
  • Add a new operator or statement form to their own interpreter (scanner, parser and evaluator) in a supervised session, and explain the change.
  • State what the halting problem says, in a few sentences, and name one consequence for software tools.
  • Predict the output of a short program under static and under dynamic scoping, and say whether a given error is caught before the program runs or while it runs in a statically and in a dynamically typed language.

Stretch goals

  • Add functions with closures to the interpreter, or compile the language to bytecode for a small stack machine.
  • Prove unaided that a given language is not regular, and show a problem undecidable by reduction from the halting problem.
  • Implement the same grammar with ANTLR and compare the result with the hand-written parser.

Assessment

Theory. Mid-term (weeks 1–7) and final (whole course, weighted to weeks 8–14) together carry 80 marks. At least half the marks are for application and analysis:

  • design an automaton or a regular expression for a described language; convert a small nondeterministic automaton to a deterministic one;
  • given a regular expression with a defect, find a string it wrongly accepts or rejects, and repair it;
  • for a given grammar, derive a string, draw the tree, show the ambiguity, and rewrite the grammar for the stated precedence and associativity;
  • trace about 30 lines of a scanner or recursive-descent parser on an input, find the defect (wrong associativity, missing lookahead) and fix it;
  • draw the syntax tree for a statement, evaluate it with an environment, and write the three-address or stack code for it;
  • predict output under static and dynamic scoping; classify errors as lexical, syntactic, static-semantic or run-time; apply reference counting to a small object graph that contains a cycle;
  • for a list of tasks ("detect every infinite loop", "check balanced brackets with a regular expression", "find the best timetable"), say which a tool can do exactly, which only approximately and which not at all, with reasons.

Recall (definitions, the Chomsky hierarchy, the compiler phases) is at most a fifth. Continuous assessment (20): four quizzes of about 15 minutes at Level 0, best three counted (10); the interpreter mini-project (10), marked 6 for the three stages and 4 for the change task.

The scanner and parser are written by hand; a parser generator is shown in week 10 but not used. Stage marks stand only if the student can explain and change their own code in week 14.

Resources

  • Michael Sipser, Introduction to the Theory of Computation (weeks 1–7).
  • John E. Hopcroft, Rajeev Motwani and Jeffrey D. Ullman, Introduction to Automata Theory, Languages, and Computation.
  • Robert Nystrom, Crafting Interpreters (basis of the mini-project; free to read online).
  • Alfred V. Aho, Monica S. Lam, Ravi Sethi and Jeffrey D. Ullman, Compilers: Principles, Techniques, and Tools (reference).
  • Michael L. Scott, Programming Language Pragmatics, or Robert W. Sebesta, Concepts of Programming Languages (weeks 11–14).
  • Software, all free: JFLAP for drawing and running automata; Python 3 or a Java development kit; grep and the regular-expression libraries of those languages; ANTLR for the week 10 demonstration; Compiler Explorer, javap and Python's dis module for looking at generated code.

Notes for the instructor

In the planned public view this section is shown to the committee only (specification 3.4).

  • The first half fails when it is taught as symbol manipulation. Tie each formal object to its use: the automaton to the scanner, the grammar to the parser, undecidability to the limits of static analysis and of AI code checkers. Keep to the two proofs and spend the time on constructions and examples.
  • For weaker students: JFLAP lets them check their own automata, a weekly problem sheet comes with worked answers, and the skeleton, fixed grammar and supplied tests mean a mid-level student finishes a working interpreter while a strong one extends it.
  • An assistant can write a whole interpreter in one answer, and solutions to well-known interpreter projects are public. Hence the course's own small language, whose grammar changes each semester, the staged submissions, and the Level 0 change task. Encourage Level 2 use for generating test programs and explaining error messages.
  • Semester 7 also carries Capstone Project I, so keep the mini-project to about 15–20 hours in total.

About this group of courses: Systems and Hardware Core

These six packages take the student from a single gate to a networked computer running many programs. Digital Logic Design (S3) builds gates, registers and state machines; Computer Organization & Architecture (S4) assembles those parts into a RISC-V processor with a memory hierarchy and shows how C becomes instructions. Semester 5 then looks at the machine from three sides: Microcontrollers & Embedded Systems programs a bare processor with no operating system, Operating Systems explains the software that shares one machine among many programs, and Computer Networks connects machines to each other. Automata, Languages & Compilers (S7) closes the sequence with what machines can and cannot compute, and how the languages used throughout the programme are translated and run.
