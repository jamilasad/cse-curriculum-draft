Rationale and what changed

This course explains what lies between a line of C and the logic circuits of CSE-2323: how instructions are encoded, how a processor executes them, and why memory access patterns decide how fast a program runs. Operating Systems and Microcontrollers & Embedded Systems in semester 5 both depend on it. The instruction set is RISC-V throughout, because it is small enough to learn completely, free to use, and well supported by free simulators; there is no 8086 material. The course has no paired lab, so the practical element is four assignments on a free RISC-V simulator. Left out: hardware multiplier and divider algorithms worked by hand, microprogrammed control, bus standards in detail, and the internals of out-of-order execution, which appears only in overview.

Minimum competency

  • Compute execution time from instruction count, CPI and clock rate, and apply Amdahl's law to one improvement.
  • Read a RISC-V function of about 20 lines (a loop, an array access, one call) and say what it computes and what named registers hold at a marked line.
  • Write and run in the simulator a RISC-V program with a loop over an array and one function call that follows the calling convention.
  • For a short instruction sequence in the five-stage pipeline, mark the data hazards and say which are removed by forwarding and which need a stall.
  • For a direct-mapped cache of given size and about ten addresses, split each address into tag, index and offset and mark each access as a hit or a miss.

Stretch goals

  • Write a recursive function in RISC-V assembly with correct stack frames and compare it with compiler output at two optimisation levels.
  • Measure the effect of loop order on matrix multiplication, in the cache simulator and on a real machine, and explain the difference.
  • Add a new instruction to the single-cycle datapath on paper: the extra hardware and the control-signal values.

There is no paired lab, so there is no lab plan. Practical work is done in the four simulator assignments described under Assessment.

Assessment

Theory. Mid-term (weeks 1–7) and final (whole course, weighted to weeks 8–14) together carry 80 marks. A RISC-V reference card and the datapath diagram are supplied in the examination, so marks do not depend on memorised encodings. At least half the marks are for application and analysis:

  • read a RISC-V function and say what it computes, or give register and memory contents after it runs;
  • find and fix a defect in an assembly routine, such as a callee that overwrites a saved register or a branch with the wrong condition;
  • translate a C loop into RISC-V; encode an instruction into 32 bits or decode a hexadecimal word;
  • trace a named instruction through the supplied datapath, give its control signals, and say what breaks if one signal is stuck at 0;
  • draw the pipeline diagram for a five-instruction sequence, mark the hazards, add forwarding or stalls, and count the cycles;
  • work a cache trace, compute average memory access time, and choose between two cache configurations or two loop orders with reasons.

Recall (stage names, formats, definitions) is at most a fifth. Continuous assessment (20): four quizzes of about 15 minutes at Level 0, best three counted (10); four simulator assignments at Level 1 (10).

Each assignment is submitted as a source file with a one-page note. Students write the assembly by hand before they are shown compiler output, and work cache traces on paper before using the cache simulator. Every student explains at least one of their four assignments at the instructor's desk; an assignment its author cannot explain earns no marks.

Resources

  • David A. Patterson and John L. Hennessy, Computer Organization and Design RISC-V Edition: The Hardware/Software Interface (main text).
  • Sarah L. Harris and David Harris, Digital Design and Computer Architecture: RISC-V Edition (continuity with CSE-2323).
  • Randal E. Bryant and David R. O'Hallaron, Computer Systems: A Programmer's Perspective (reference for the programmer's view; it uses x86-64).
  • Software, all free: RARS (assembler and simulator); Ripes (visual datapath, pipeline and cache simulator); Compiler Explorer or a RISC-V build of GCC for viewing compiler output. No hardware is needed.

Notes for the instructor

In the planned public view this section is shown to the committee only (specification 3.4).

  • With no lab, the simulator has to appear in lectures. Project it, step through programs, and ask students to predict register values before each step. Where a computer lab is free, hold one hour in it every second week.
  • Students memorise the datapath figure without being able to follow an instruction through it. Always examine by tracing, never by asking for the figure to be reproduced. In assembly the common confusion is between a value and an address; tie it back to pointers in CSE-1221.
  • For weaker students, reading comes before writing: a graded set of ten-line programs to read each week, the reference card always allowed, and repeated drills on splitting an address into tag, index and offset.
  • Assistants translate C into RISC-V readily. That is why the assignments carry only 10 marks, are checked by oral explanation, and the examination tests reading and tracing. A useful exercise: ask an assistant for a routine, then check it against the calling convention in the simulator.

About this group of courses: Systems and Hardware Core

These six packages take the student from a single gate to a networked computer running many programs. Digital Logic Design (S3) builds gates, registers and state machines; Computer Organization & Architecture (S4) assembles those parts into a RISC-V processor with a memory hierarchy and shows how C becomes instructions. Semester 5 then looks at the machine from three sides: Microcontrollers & Embedded Systems programs a bare processor with no operating system, Operating Systems explains the software that shares one machine among many programs, and Computer Networks connects machines to each other. Automata, Languages & Compilers (S7) closes the sequence with what machines can and cannot compute, and how the languages used throughout the programme are translated and run.
