Rationale and what changed

Java is the students' first statically typed, object-oriented language and the one most used in enterprise software. With Programming I and II this course completes the three-course sequence that replaces Computer Programming I and II of the 2022 syllabus, and it is the first of the three courses that carry software design for accreditation. Design is taught by refactoring working code under tests: principles and a few patterns are met as the result of a refactoring, not as a list to memorise, and UML is used only as a quick sketch. The lab ends with a small pair project run with Git feature branches and code review, in which AI use moves from Level 1 to Level 2; this is the programme's first Level 2 work and it is closely supervised. Left out: graphical interfaces, threads, the full pattern catalogue, full UML notation, frameworks such as Spring, and database access (CSE-2423).

Minimum competency

Every passing student can, unaided on a lab machine:

  • Write a class with private state, a constructor that rejects invalid values and methods that keep the object valid, and write JUnit tests for it.
  • Given two or three classes with duplicated behaviour, introduce an interface so that the calling code works with any implementation.
  • Choose and use ArrayList, HashMap and HashSet for a given task, iterate over them, and handle a checked exception without swallowing it.
  • Read a sketch of five or six classes and write the class skeletons; draw the sketch for given code.
  • Create a branch, open a pull request, answer a review comment and merge.

Stretch goals

  • Recognise where a refactoring leads to Strategy, Observer or Factory, apply it, and state what it costs.
  • Use records, lambdas and streams to shorten collection-processing code without making it harder to read.
  • Have the test suite run automatically on every pull request with a continuous-integration service.

Assessment

Theory. The written mid-term and final (80) are made of:

  • Read and predict (about 20%): the output of code involving dynamic dispatch, aliasing, == versus equals, and the path through try/catch/finally.
  • Repair a class (about 15%): a class with public fields or a constructor that accepts invalid values; show how its invariant can be broken and rewrite it.
  • Redesign (about 25%): a method with a chain of type checks, or a 40-line method with several smells; name the problems and write the improved code with an interface or extracted classes.
  • Choose and use (about 15%): pick a collection for a scenario, justify it and write the code; decide between inheritance and composition for a described case.
  • Tests and sketches (about 10%): write JUnit tests for a specification, or say which cases a given test class misses; write class skeletons from a sketch, or the sketch from code.
  • Recall (about 15%): terms such as encapsulation, checked exception and interface.

Continuous assessment (20): short quizzes at Level 0 (10); two assignments at Level 1 (10), one modelling a small domain as tested classes and one refactoring a given program, each followed by a short question in class on the student's own submission.

Resources

  • Textbooks: Cay S. Horstmann, Core Java, Volume I: Fundamentals; Kathy Sierra, Bert Bates and Trisha Gee, Head First Java; Martin Fowler, Refactoring: Improving the Design of Existing Code; Joshua Bloch, Effective Java (for stronger students).
  • Software: OpenJDK (a current long-term-support release); IntelliJ IDEA, Eclipse or VS Code with the Java extensions; JUnit; Maven or Gradle; Git with GitHub or the department's Git server.

Notes for the instructor

In the planned public view this section is shown to the committee only (specification 3.4).

  • Students can recite the "four pillars" and the names of patterns and still not be able to design. Ask for redesigns of given code in every examination, never for definitions of patterns. Teach interfaces and composition (weeks 5–6) before inheritance (week 7), or inheritance becomes the default tool.
  • Students arrive from C writing one large main with everything static and public. The first five labs use many small classes with tests supplied, so that a passing test gives the weaker student immediate feedback. Design discussion may be in Bangla; identifiers, comments and documents are in English.
  • Assistants produce class hierarchies and boilerplate at once, often with more abstraction than the problem needs. What remains to be learnt is judging a design and keeping it small, which is why week 11 reviews AI-written code and why the viva covers the partner's code and the AI-assisted parts.
  • Form pairs from students of similar level; a strong–weak pair usually produces one author and one passenger. A student without meaningful commits and reviews of their own does not receive the project mark.

About this group of courses: Programming and Algorithms

These seven packages form the programming spine of semesters 1 to 4. Programming I (Python) builds the habits of tracing, decomposing, testing and debugging, and the Developer Tools & Technical Communication Lab supplies the shell, Git, editor and writing skills that every later lab assumes. Programming II (C) adds the memory model; Data Structures (C++) and Object-Oriented Programming & Design (Java) build on it in semester 3, and Algorithms in semester 4 turns structures into design techniques. The Core Competency Assessment then checks, unaided, the floor these courses are meant to produce, before students move on to the track courses and the capstone. while permitted AI use rises from Level 0 in semester 1 to Level 2 in later projects and stays at Level 0 in every test, viva and examination.
