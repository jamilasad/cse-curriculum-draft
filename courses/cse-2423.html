Rationale and what changed

Almost every software job reads and writes a relational database, and the Core Competency Assessment (CSE-2440) in the same semester tests SQL at Level 0. Databases stay a full course, as in the 2022 syllabus, but the order changes: SQL comes first (weeks 2–5) so that the Software Engineering Studio can use it, and design theory follows once students have met the problems it solves. Relational algebra is kept only as far as it explains what a query means and how a plan executes; relational calculus, the hierarchical and network models, and file-organisation detail are left out. The new material is short and placed last: non-relational stores and vector search, which the AI studio in semester 6 depends on. By hand first: every student writes queries, schemas and normalisation steps unaided in psql. With tools afterwards: graphical clients, an object-relational mapper seen from the outside, and, in the lab project, an AI assistant whose SQL the student must check against the data and the query plan.

Minimum competency

  • Given an unseen schema of five to eight tables, write correct queries using inner and outer joins, GROUP BY with HAVING, and a subquery, in psql with no assistance.
  • Turn a half-page requirement into an ER diagram and then into CREATE TABLE statements with primary keys, foreign keys and constraints.
  • Given a table and its functional dependencies, find a candidate key and decompose the table to third normal form.
  • Using two sessions, show a lost update and then prevent it with a transaction.
  • Run EXPLAIN on a query, say whether an index is used, and add an index that changes the plan.

Stretch goals

  • Implement a B+-tree with insert, search and range scan in C++ and compare its page reads with those of a sorted file.
  • Reproduce write skew under snapshot isolation in PostgreSQL, remove it with SERIALIZABLE or explicit locking, and write up the difference.
  • Build hybrid search (full-text plus vector) over a small Bangla and English document set and measure recall against hand-labelled queries.

Assessment

Theory (100). Written mid-term and final (80). At least half the marks are application and analysis: write a query for a stated question on a printed schema; give the output of a given query on given rows; say why a query returns duplicate or missing rows (a wrong join, a NULL comparison, a misplaced HAVING) and correct it; draw an ER diagram for a short case and map it to tables; find the keys of a given table and normalise it; name the anomaly in an interleaved schedule and the weakest isolation level that prevents it; read a printed EXPLAIN output and propose an index; choose a type of store for a described workload. Recall (the ACID properties, definitions of the normal forms) is at most a fifth. Continuous assessment (20): four short Level 0 quizzes, mostly query writing on paper (10); two assignments, a graded query set and a schema design with a written normalisation argument (10).

Lab (100). Weekly lab work and lab record 30; two supervised practical tests at Level 0 in weeks 6 and 12, 30; lab project 25; individual viva 15. The project, done in pairs, is the database of a small organisation (a diagnostic centre, a coaching centre, a courier service): ER diagram, 8–12 normalised tables with constraints, seed data, 15 named queries including reports, two indexes justified by plan output, one multi-statement operation made safe by a transaction, a small program that uses the database, and a README in English. A student who cannot explain their own project in the viva does not pass the lab.

Resources

  • Textbooks: Silberschatz, Korth and Sudarshan, Database System Concepts; Elmasri and Navathe, Fundamentals of Database Systems; Kleppmann, Designing Data-Intensive Applications (selected chapters for weeks 9–14); Winand, SQL Performance Explained.
  • Software, all free: PostgreSQL (preferred) or MySQL; psql or the mysql client; DBeaver or pgAdmin; the pgvector extension; Redis; MongoDB Community Edition (optional); diagrams.net for ER diagrams.
  • Hardware: nothing beyond the ordinary computer labs.

Notes for the instructor

In the planned public view this section is shown to the committee only (specification 3.4).

  • Common failures: students memorise query patterns and collapse on a new schema, so change the schema between practice and test and require a predicted result before each query is run. Normalisation turns into symbol pushing, so start each step from real rows that show an update anomaly and name the normal form only afterwards.
  • Weaker students: one sample schema with familiar data (students, courses, results, payments) is used all semester; a one-page SQL reference is allowed in weekly labs but not in tests; an ungraded drill set of ten queries is issued every week, and the CSE-2440 remedial clinics reuse those sets.
  • AI: assistants produce fluent SQL that is often wrong on NULLs, duplicates and join cardinality. In weekly labs and assignments they may explain an error but not write the query (Level 1); in week 11 students check AI-written suggestions supplied by the instructor, and in the project, once the schema is approved, they may use assistants (Level 2) but must verify the output against the data and the plan.
  • Coordinate with CSE-2434 and CSE-2440: the studio needs CREATE TABLE, INSERT, SELECT and joins by its week 3, and the first CSE-2440 sitting should fall after lab test 1.

About this group of courses: Software, Data, AI and Security Core

These six packages run from semester 4 to semester 6 and carry the part of the core in which students build, secure, deploy and extend real software. Database Systems and the Software Engineering package share semester 4: the database course teaches SQL early enough for the studio to use it, and the web application built in the studio becomes an object that later courses return to. Artificial Intelligence & Machine Learning (semester 5) gives the foundations and the habit of honest evaluation that the AI Application & Agent Engineering Studio (semester 6) turns into a shipped product. In semester 6, Information Security attacks and hardens the semester-4 application and Distributed Systems & Cloud Computing containerises, deploys and monitors it, so each student meets the same piece of software as its builder, its attacker and its operator.
