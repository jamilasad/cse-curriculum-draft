Rationale and what changed

The second programming course uses C to show what Python hid: where values live, what a pointer is, how source code becomes a running process, and why programs crash. It takes the place of Computer Programming II and its lab in the 2022 syllabus, but it is not a second syntax course: control flow is revised in two weeks by porting familiar Python programs, and the rest of the semester goes to the memory model, the build chain and the tools that find memory errors. It prepares directly for Data Structures (pointers and dynamic memory), Operating Systems (processes, files, system calls) and Microcontrollers & Embedded Systems (bit operations, C close to hardware). Left out: C++ features, threads, sockets, build systems beyond make, and advanced preprocessor use.

Minimum competency

Every passing student can, unaided on a lab machine:

  • Given a 20-line C fragment with pointers and an array, draw memory after each marked line and state the output.
  • Write a function that receives an array with its length, or a string, and processes it without reading or writing outside its bounds.
  • Allocate, grow with realloc and free a dynamic array of structs with no leak and no invalid access, confirmed by AddressSanitizer or Valgrind.
  • Build a three-file program with a header and a Makefile, and fix one given compile error and one given link error.
  • Use gdb to find the line and the cause of a segmentation fault in a given program.

Stretch goals

  • Write a small dynamic-string or vector library with a clean header, tests and no leaks.
  • Read the assembly that gcc -S produces for small functions and relate it to the stack-frame diagrams.
  • Write a command-line tool such as a hex dump or a word counter that handles files of any size.

Assessment

Theory. The written mid-term and final (80) are made of:

  • Memory diagrams (about 25%): draw the stack and heap after each marked line of a pointer program and write the output.
  • Find the defect (about 20%): code with an out-of-bounds write, a missing terminating zero, a leak or a dangling pointer; name the defect, give an input that triggers it and correct it. Some questions give a Valgrind or AddressSanitizer report with the source and ask for the cause.
  • Write (about 20%): a function to a given prototype, such as int count_char(const char *s, char c), or a function that appends to a dynamic array.
  • Build and link (about 10%): given two source files and an error message, say whether the compiler or the linker produced it and fix it; write a Makefile rule.
  • Representation and bits (about 10%): convert values, predict an overflow, write the expression that sets, clears or tests a bit.
  • Recall (about 15%): the stages from source to process; the meaning of static, const and sizeof.

Continuous assessment (20): weekly memory-diagram quizzes at Level 0 from week 4, best six counted (10); three programming assignments at Level 1 (10), each confirmed by a short written question in class on the student's own code.

Resources

  • Textbooks: Brian W. Kernighan and Dennis M. Ritchie, The C Programming Language; K. N. King, C Programming: A Modern Approach; Randal E. Bryant and David R. O'Hallaron, Computer Systems: A Programmer's Perspective (selected chapters, teacher's reference for weeks 3, 10 and 14).
  • Software: GCC or Clang, GNU Make, GDB, Valgrind, AddressSanitizer (part of GCC and Clang), VS Code, Git; Linux lab machines, or WSL on students' own Windows laptops so that the tools behave the same.
  • Printed memory-diagram sheets; a Makefile template with warning and sanitizer flags switched on.

Notes for the instructor

In the planned public view this section is shown to the committee only (specification 3.4).

  • Pointers fail when they are taught as syntax. Start every pointer topic from a diagram and run diagram quizzes weekly from week 4; a student who cannot draw the picture cannot debug the program.
  • "It ran once" is not evidence in C. Compile with -Wall -Wextra -Werror from week 2 and with -fsanitize=address -g by default, so that silent memory errors become visible reports.
  • For weaker students, weeks 1–2 port programs they already wrote in Python, so that only the language is new. Give partly drawn diagrams before blank ones, allow pair work at the bench, and run a weekly support hour for those who fail two diagram quizzes.
  • Assistants write fluent C, including C with memory errors that compiles and appears to work. Show students how to ask for an explanation of a crash and then check that explanation against gdb; the assistant guesses without seeing the run. The assessed skill is checking, by diagram, tool and test.

About this group of courses: Programming and Algorithms

These seven packages form the programming spine of semesters 1 to 4. Programming I (Python) builds the habits of tracing, decomposing, testing and debugging, and the Developer Tools & Technical Communication Lab supplies the shell, Git, editor and writing skills that every later lab assumes. Programming II (C) adds the memory model; Data Structures (C++) and Object-Oriented Programming & Design (Java) build on it in semester 3, and Algorithms in semester 4 turns structures into design techniques. The Core Competency Assessment then checks, unaided, the floor these courses are meant to produce, before students move on to the track courses and the capstone. while permitted AI use rises from Level 0 in semester 1 to Level 2 in later projects and stays at Level 0 in every test, viva and examination.
