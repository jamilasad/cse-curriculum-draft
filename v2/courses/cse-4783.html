Rationale and what changed

Models and dashboards are only as good as the data behind them, and many of the data jobs open to graduates are in moving, modelling and explaining data, not in training models. The 2022 syllabus touched this only as data mining inside the machine-learning course; it had nothing on warehouses, pipelines, data testing or dashboards. This course builds on the core Database Systems course, which covers transactional design, and adds the analytical side. It leaves out the administration of large clusters (the department has none; distributed processing is taught as concepts and on a single node), vendor-specific warehouse features and advanced statistics. Students write analytical SQL by hand before any tool generates it, and load a warehouse with plain SQL before using a transformation framework and an orchestrator.

Minimum competency

Every passing student can, unaided:

  • Given a star schema, write correct SQL with joins at the right grain, GROUP BY, a common table expression and a window function (rank, running total or lag), and check the totals against the source.
  • Given a business question and source tables, draw a star schema and state the grain of the fact table in one sentence.
  • Build a pipeline of at least three dependent steps that can be run twice without duplicating rows, with at least three automated data tests.
  • Read the log of a failed pipeline run and identify the failing step and its cause.
  • Produce a chart that answers a stated question (suitable chart type, labelled axes, a title that states the finding), and mark and mask the personal-data columns of a given table.

Stretch goals

  • Process a dataset larger than memory on one machine with DuckDB and with single-node Apache Spark, and compare time and effort.
  • Add change data capture from PostgreSQL, or a lakehouse table format (Apache Iceberg or Delta Lake) with schema evolution and time travel, to the project pipeline.
  • Publish a public data project with documentation, or have a fix accepted by an open-source data tool.

Weekly plan — lab

CSE-4784 Data Engineering & Analytics Lab · Lab · 1 credits · 2 contact hours a week

Compute: everything runs on an ordinary lab PC with free software: PostgreSQL and DuckDB as the warehouse, a transformation framework, an orchestrator, a single-node message broker and an open-source dashboard tool. Lab PCs have limited memory, so services are run one at a time; where a PC cannot run the broker or the dashboard server, the instructor hosts one for the section. No cloud account is required, though a free tier may be used for the project. Lab work is at Level 2: AI assistants may write pipeline code under the disclosure conditions. Week 11 is at Level 3, because AI-written SQL is itself the thing being tested.

Assessment

Theory. Mid-term (weeks 1–7) and final, 80 marks. At least half the marks are application and analysis: write by hand the output of a window-function query on small printed tables; find why a query double-counts and correct it; design a star schema for a case such as a pharmacy chain or a ride-sharing service, stating the grain and the type of each changing dimension; say what a given pipeline does when it is run twice and make it idempotent; assign timestamped events, including late ones, to windows by hand; list the checks a printed table sample fails and write the tests; choose batch or streaming for three requirements; redraw a misleading chart and rewrite its title; identify personal data in a schema and propose masking and roles. Recall carries at most a fifth of the marks. Continuous assessment, 20: four Level 0 quizzes, mostly SQL on paper, best three counted (10); one analytical brief of one page with one chart from a supplied dataset, marked with the shared writing rubric (10).

Lab (100). Weekly lab work and lab record 30; two supervised practical tests 30 (15 each, offline documentation allowed); lab project 25; individual viva 15. The project, in pairs, is an analytics product for a real or realistic organisation: at least two sources, ingestion, a layered warehouse with a dimensional model, orchestration, automated tests, a dashboard, a one-page brief of findings and a short data-handling note. SWE students may build the analytics side of their own capstone application. A student who cannot explain their own submitted work in the viva does not pass the lab.

Resources

  • Textbooks: Reis and Housley, Fundamentals of Data Engineering; Kimball and Ross, The Data Warehouse Toolkit; Kleppmann, Designing Data-Intensive Applications; Knaflic, Storytelling with Data; Wilke, Fundamentals of Data Visualization. For the streaming weeks: Akidau, Chernyak and Lax, Streaming Systems.
  • Software (free and open): PostgreSQL, DuckDB, Python with pandas and PyArrow, dbt Core, one orchestrator (Apache Airflow, Dagster or Prefect; Airflow needs the most memory), Apache Kafka or Redpanda, one validation library (Great Expectations, Soda Core or pandera), Apache Superset or Metabase (Streamlit as a lighter alternative), Docker, Git; Apache Spark on a single node for the stretch work.
  • Data: an instructor-built retail dataset with a generator for daily files and events; public datasets; anonymised extracts from partner organisations.

Notes for the instructor

In the planned public view this section is shown to the committee only (specification 3.4).

  • The commonest error is a join that multiplies rows and a total that nobody checks. Require a reconciliation line (pipeline total against source total) in every lab deliverable from week 1.
  • AI assistants produce SQL and pipeline code quickly, and they get the grain wrong or invent column names without any warning. Teach students to supply the schema, ask for tests and reconcile. The week 11 lab makes them measure the error rate themselves.
  • This is the course in which mid-level students can become employable: sound SQL, one tested pipeline and a clear dashboard are enough for a junior data role. Give weaker students graded SQL sets in weeks 1–3 and a weekly SQL clinic, and give sentence frames for the brief.
  • The class mixes AID and SWE students, so assume no machine learning beyond the core. Tools in this field change fast; teach the patterns (grain, idempotent load, tests, task graph) and treat the named tools as this year's examples.
