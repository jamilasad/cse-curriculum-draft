Rationale and what changed

This is the first programming course for students who mostly have not programmed before and who read English slowly. It takes the place of Computer Programming I and its lab in the 2022 syllabus, but its aim is different: the student learns to solve small problems, to read and trace code, to test and to debug, and Python is used because it puts the least syntax between the student and those skills. Tracing comes before writing in every topic, and practice is given as many small supervised exercises, not as a large project. Left out on purpose: classes and objects (CSE-2325), memory and pointers (CSE-1221), comprehensions, lambdas, decorators, third-party libraries and graphical interfaces. AI assistants are not used at all; the reason is explained to students in CSE-1130.

Minimum competency

Every passing student can do the following on a lab machine with no AI tool, no internet and no notes:

  • Trace a 15–20 line program containing a loop, a condition and a list, and write its exact output.
  • Write, from a short written specification, a function containing a loop and a condition (for example, count the marks in a list that are at or above a pass mark) that passes the tests supplied.
  • Given a 30-line program with one syntax error, one run-time error and one logic error, find and fix all three.
  • Write at least four test cases for a given function, including an empty or boundary input, and say what each case checks.
  • Read a text file line by line, compute a count, total or maximum from it, and print the result.

Stretch goals

  • Solve small problems recursively and compare the recursive and loop versions by tracing both.
  • Write a program of 150–200 lines split across two modules, with a test file.
  • Work through the beginner problems on the department's online judge, which the class meets formally in CSE-2322.

Assessment

Theory. The written mid-term and final (80) are made of:

  • Tracing (about 30%): write the output of a given program; complete a trace table; draw the names and lists after an aliasing step.
  • Repair (about 20%): a program and its wrong output are given; find the faulty line, explain the fault and correct it.
  • Arrange and complete (about 10%): put shuffled lines into a working order, or fill in the missing lines of a function.
  • Write (about 25%): a function of 10–20 lines from a specification with examples; small syntax slips are not penalised.
  • Test design (about 5%): list test cases for a specification and say what each one checks.
  • Recall (about 10%): what a given built-in or method does; the difference between two terms.

Continuous assessment (20): ten-minute paper quizzes on tracing in most weeks, best eight counted (10); weekly homework sets (10), where the mark is given only after the student re-solves or explains one randomly chosen homework problem in class.

Resources

  • Textbooks: Allen B. Downey, Think Python; John Zelle, Python Programming: An Introduction to Computer Science; Al Sweigart, Automate the Boring Stuff with Python (extra practice).
  • Software: Python 3; Thonny in weeks 1–7 for its step-by-step debugger; VS Code with the Python extension and Git from week 8; pytest; an offline copy of the Python documentation.
  • Printed trace-table sheets, and a course glossary of about 80 English terms with Bangla explanations, shared with CSE-1130.

Notes for the instructor

In the planned public view this section is shown to the committee only (specification 3.4).

  • The usual failure is asking students to write before they can trace. Hold new syntax back until the weekly tracing quiz shows the class can read it. = versus ==, print versus return and off-by-one loop bounds need repeated tracing, not repeated explanation.
  • A student who fails two tracing quizzes in a row is called to a weekly support hour run by the lab instructors. Weaker students start from shuffled-line and fill-the-gap tasks before blank-page tasks. Students may work in pairs at the bench, but every test is individual.
  • Written work stays in simple English and no mark depends on grammar. At the bench and in the viva, let a student explain in Bangla when English is the obstacle; the technical terms stay in English.
  • An AI assistant solves every exercise in this course in seconds, so homework carries few marks and everything that counts is done under supervision. Do not rely on AI-detection tools. Tell students plainly that these exercises build the reading and checking skill they will need to supervise AI output from semester 4 onward.

About this group of courses: Programming and Algorithms

These seven packages form the programming spine of semesters 1 to 4. Programming I (Python) builds the habits of tracing, decomposing, testing and debugging, and the Developer Tools & Technical Communication Lab supplies the shell, Git, editor and writing skills that every later lab assumes. Programming II (C) adds the memory model; Data Structures (C++) and Object-Oriented Programming & Design (Java) build on it in semester 3, and Algorithms in semester 4 turns structures into design techniques. The Core Competency Assessment then checks, unaided, the floor these courses are meant to produce, before students move on to the track courses and the capstone. while permitted AI use rises from Level 0 in semester 1 to Level 2 in later projects and stays at Level 0 in every test, viva and examination.
