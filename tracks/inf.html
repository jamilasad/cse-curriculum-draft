Who it suits

This is the track where mid-level students do best, and it is a demanding track, not a lesser one: the systems it teaches carry a bank's transactions and an operator's subscribers, and a mistake is seen at once. The work rewards care, practice and following a method more than mathematical talent. A student who does every lab, keeps an exact record and checks before acting becomes employable, and certificates let that student show it with evidence that does not depend on CGPA. Strong students find depth here too, in network design, automation and reliability engineering. Every course includes scripting, so the track is not a way to avoid programming, and many of its jobs involve shift work and on-call duty. A student who wants to spend the day writing application code should look at SWE.

What students already know

  • Python (CSE-1121) and C (CSE-1221); the Linux shell and Git from the Developer Tools & Technical Communication Lab (CSE-1130, semester 1), checked unaided in the Core Competency Assessment (CSE-2440).
  • Operating Systems with its Linux lab (CSE-3541, CSE-3542): processes, threads, memory and file systems seen through system calls, and one container exercise.
  • Computer Networks with its lab (CSE-3543, CSE-3544): the layers, subnetting, one VLAN, static routes and single-area OSPF in a simulator, sockets, DNS, TLS and one access list; part of the CCNA syllabus.
  • Microcontrollers & Embedded Systems (CSE-3547, CSE-3548): comfort with hardware, serial links and data sheets, which helps with console access and server hardware.
  • In semester 6, alongside Track Course I: Information Security (CSE-3651, CSE-3652), and Distributed Systems & Cloud Computing with the Cloud & DevOps Lab (CSE-3653, CSE-3654), which covers a systemd service, Docker and Compose, a CI pipeline, a local Kubernetes cluster, Prometheus and Grafana, and one Terraform or OpenTofu exercise.

The track does not re-teach these. CSE-3677 works on the host beneath the containers and leaves containers and Kubernetes to CSE-3654 and CSE-4787.

AI assistants in operations work

Assistants now draft shell scripts, Ansible playbooks, firewall rules and router configurations in seconds, and they help in reading unfamiliar logs and error messages. They are also wrong with confidence: an option from another distribution or software version, a rule that opens more than was asked, a command that deletes data or cuts off the administrator's own remote access. In operations the command runs on a system that other people depend on. All four courses therefore teach one rule: a draft from an assistant is treated as a change proposed by an unknown colleague. The engineer reads every line, runs it first in a test environment (a virtual-machine snapshot, an emulated topology, a check or dry-run mode), prepares the way back, and only then applies it to a real system through change control. Passwords, keys, real configurations and customer data are never pasted into a public assistant. Weekly lab work and assignments are at Level 2, with prompts logged and test evidence attached; examinations, quizzes, lab tests and vivas are at Level 0, which is also the engineer's situation during an outage when the assistant cannot see the system.

Substitutions

Framework section 9 applies. CSE-3677 is Track Course I and cannot be replaced; for the same reason it is not open to students of other tracks as a substitute. CSE-4787 is a prerequisite of CSE-4887, so it cannot be swapped either. With the adviser's approval, an INF student may replace CSE-4777 in semester 7 with Web & Application Security (CSE-4775, SEC track), which needs no SEC course before it. This suits a student aiming at infrastructure or application security; a student heading for network engineering should keep CSE-4777. The other semester-7 SEC course, Digital Forensics & Incident Response, is not available as a swap, because it requires the SEC track's Network Security & Security Operations. The rules also allow CSE-4887 to be replaced by another track's semester-8 course, but the framework names no natural pairing, and CSE-4887 is the course closest to the track's jobs.

In the other direction, Cloud Infrastructure & Virtualization (CSE-4787 + CSE-4788) is a natural substitution for SWE and SEC students. They have not taken CSE-3677, so they should work through the CSE-3678 lab sheets for weeks 1–5 in the vacation before semester 7.

Competency gate

A pass in CSE-2440 is required before a student registers for CSE-4777 and CSE-4787 (and Capstone Project I). CSE-3677 does not require it, so a student can begin the track while still working towards a pass. The Linux and Git parts of CSE-2440 overlap with CSE-3678 weeks 1–5, which makes the semester-6 lab good preparation for a resit, but a student who has not passed by the end of semester 6 loses a semester of track courses. Advisers should identify these students when tracks are chosen at the end of semester 5 and send them to the remedial clinics.

Lab environment and equipment

Most of the track runs in the existing computer labs: virtual machines in VirtualBox or KVM on lab PCs (Rocky Linux or AlmaLinux, and Ubuntu Server), with a department server hosting shared machines for PCs too small to run three VMs; network emulation in Cisco Packet Tracer for Cisco-style command practice and in GNS3 or containerlab with FRRouting and Linux hosts for larger and multi-vendor topologies; and free cloud tiers and education programmes for CSE-4787, used with spending alerts. The lab network segment has no route to the campus network, so that a student's stray DHCP server or switching loop disturbs nobody else.

Real equipment worth buying is one small rack, shared with the SEC track:

Used enterprise equipment is adequate. Devices with a Cisco IOS-style command line match the CCNA syllabus and Packet Tracer; any vendor teaches the concepts. Each lab group gets real-device time in about three sessions per course, in rotation; everything else is done in emulation. No storage array, blade chassis or paid software licence is needed.

Suggested capstone direction

INF capstones deliver an infrastructure design, migration or automation for a real organisation, with monitoring and a runbook (CSE-4700, CSE-4800). Directions that fit: rebuilding a small organisation's servers (a school, an NGO, a local firm, a university office) as code, with monitoring, backups and a tested restore; redesigning the network of a multi-floor building, from survey and addressing plan through VLANs and wireless plan to a staged cut-over and documentation; moving a service from a single machine onto a virtualised or cloud platform, with a cost comparison and a rollback plan; or a configuration-backup and compliance-check tool for a fleet of network devices, tested on the rack and in emulation. Work on a client's live systems needs written approval, is rehearsed in a test environment first, and is done in the client's change window.
