The track has four courses, each a 3-credit theory course with a 1-credit lab: CSE-3671/3672 in semester 6, CSE-4771/4772 and CSE-4781/4782 in semester 7, and CSE-4881/4882 in semester 8. Its aim is to move a student from "can build a CRUD application" to someone who can decide how a system should be structured, show that it works, and keep it running. Routine application coding is the work most exposed to AI tools; these three abilities are what a junior engineer is still paid for.

Jobs the track leads to

  • Software engineer (back end, front end or full stack) in Bangladeshi firms that build and maintain web, mobile and enterprise applications for clients in the United States and Europe, in development centres of foreign companies, and in domestic fintech and platform companies. This is the main destination.
  • Mobile application developer using a cross-platform framework.
  • Test automation engineer or software development engineer in test (SDET).
  • Junior DevOps, platform, cloud or site reliability engineer.
  • Remote employee or contractor for a foreign company, for students with good English and a public record of work.
  • With experience: technical lead, solution architect, engineering manager.

Who it suits

Any student who has passed the core and wants to build software for a living. It is the default track and will be the largest.

  • Strong students should use it to reach architecture, back-end and platform work in product companies. The stretch goals in each course point at open-source contribution and other public evidence.
  • Mid-level students have three dependable routes through it: test automation, front-end and mobile work, and operations. Each rests on skills that can be learned by procedure and practice and checked in a practical test: deriving test cases, auditing a page for accessibility, finding the fault in a broken deployment.
  • A student who struggled in the semester-4 studio can pass, because every course has guided labs and a checked floor, but should expect extra hours of code reading each week. The adviser should discuss INF with such a student before the choice is made.
  • The track demands a great deal of reading and writing in English: review comments, decision records, defect reports, postmortems. That is the daily work with foreign clients, and it is marked.
  • A student who prefers systems to application code should look at INF; one who is strong in mathematics and wants model work should look at AID.

What students already know when they start

By the end of semester 5 every student has completed:

  • Programming I and II (Python, C), Data Structures (C++) and Object-Oriented Programming & Design (Java): writing, testing and debugging programs of a few hundred lines, and design at class level.
  • Algorithms and Database Systems: complexity, SQL, relational modelling, transactions.
  • Software Engineering and its studio (CSE-2433, CSE-2434): requirements, Git with pull requests, and one team web application in JavaScript/TypeScript and SQL.
  • Operating Systems and Computer Networks: processes, memory, concurrency, TCP/IP, HTTP, DNS.
  • Artificial Intelligence & Machine Learning, and Microcontrollers & Embedded Systems.

In semester 6, beside Track Course I, they take Information Security (CSE-3651), Distributed Systems & Cloud Computing with the Cloud & DevOps Lab (CSE-3653, CSE-3654) and the AI Application & Agent Engineering Studio (CSE-3660). The semester-7 and semester-8 track courses therefore assume secure-coding basics, containers, a CI/CD pipeline, a first cloud deployment, and experience of building and evaluating an LLM feature.

What they have not yet done: worked in a codebase they did not write, been answerable for the quality of software, or kept a service running for users. The track is built on those three gaps.

The track relies on four things in core outlines that are written separately. If any is not so, the track course named needs an extra week:

  • CSE-2434 has students write routing, data access and session handling with little framework help (assumed by CSE-4771).
  • CSE-2325 introduces unit testing with JUnit (assumed by CSE-4781).
  • CSE-3654 has every student build a container image and deploy an application through a pipeline (assumed by CSE-4781 and CSE-4881).
  • CSE-3660 introduces evaluation of LLM features (assumed by CSE-4781).

How the four courses build on each other

SemesterCourseQuestion it answersWorks on
S6CSE-3671 Software Architecture & DesignHow should a system be structured, and how do I change one I did not write?An existing medium-sized codebase
S7CSE-4771 Full-Stack & Mobile Application EngineeringHow do I build a complete product at realistic scale with frameworks and AI assistance?A new team product
S7CSE-4781 Software Testing & Quality EngineeringHow do I know it works and will keep working?A seeded application, then the CSE-4772 product
S8CSE-4881 Cloud-Native Engineering & Site ReliabilityHow do I run it for real users and respond when it fails?A reference system, then the capstone system

The order is design, build, verify, operate. CSE-3671 comes first so that the semester-7 product is designed before it is built. The two semester-7 courses run side by side on one product: it is built in CSE-4772 and tested in CSE-4782. CSE-4881 takes a working product into production conditions while the student is also seeing a real workplace in Industry Practice. The same piece of work is never marked twice: each course marks its own aspect.

All four labs share working practices so that they become habit: work lives in a Git repository; changes go through pull requests with written review in English; decisions are recorded as architecture decision records (ADRs); AI assistance at Level 2 is logged; practical tests and vivas are at Level 0 on lab machines.

Suggested capstone direction

Teams of three or four build and run a production-quality system for a real client or user group, or modernise a real legacy system in stages. Suitable clients are close at hand: a clinic or diagnostic centre, a school or madrasa, a small manufacturer or shop, an NGO field programme, a university office. Modernising an existing system is especially good preparation, because it is what service firms do for foreign clients.

What separates a SWE capstone from a large CRUD project is the evidence required:

  • an architecture description with decision records and stated targets for performance, availability and accessibility (CSE-3671);
  • a web client, an API and, where the users need it, a mobile client (CSE-4771);
  • an automated test suite running in CI, and a quality report (CSE-4781);
  • deployment from code, dashboards, at least one service-level objective, and a postmortem of a real or drilled incident (CSE-4881);
  • at least four weeks of use by real users during Capstone II, with usage and incident data in the report.

Capstone I (semester 7) runs beside CSE-4771 and CSE-4781, and Capstone II (semester 8) beside CSE-4881, so each course can be applied to the capstone as it is taught.

Substitution from another track

The framework allows one of Track Courses II–IV (CSE-4771, CSE-4781 or CSE-4881) to be replaced by a course from another track offered in the same semester, with the adviser's approval. Track Course I, CSE-3671, cannot be replaced. The sensible substitutes for SWE students are all in semester 7.

CSE-3671 is the base of the track and is not open to substitution. CSE-4881 could be replaced only by another track's semester-8 course; this is not advised, because it is where the track ends. A mid-level student aiming at test automation should keep CSE-4781. The "Replaces" column assumes that courses in the same slot are timetabled together; if they are not, the adviser may choose which SWE course is given up.

Substitution checker

Overlap. Track Course I (semester 6) is each track's foundation and cannot be replaced. A student may replace one of Track Courses II–IV with a course from another track offered in the same semester, with the adviser's approval. A course that is a prerequisite of the student's own semester-8 track course cannot be swapped; in practice an AID student may swap only CSE-4783 and an INF student only CSE-4777. Natural substitutions, all in semester 7: Data Engineering & Analytics or Web & Application Security for SWE students; Cloud Infrastructure & Virtualization for SWE or SEC students; IoT Systems & Edge AI for AID students.
